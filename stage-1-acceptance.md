# Этап 1 · Протокол технической приёмки

**Статус — этап 1 принят.** Финальные измерения и результат очереди приведены в разделе «Итог».

## Подтверждено локально

- FFmpeg декодирует тестовый MP4, измеряет громкость, пики и интервалы тишины. Файл без аудиодорожки отклоняется.
- Нарезка и вертикальный экспорт сохраняют аудиодорожку и заданную длительность.
- Импорт расшифровки работает через HTTP и PostgreSQL (PGlite). Повтор возвращает ту же версию.

## Зафиксированные решения

- Анализ расшифровки — основной режим Gemini. Публичная YouTube-ссылка — экспериментальный режим. Если провайдер отвергает URL или не возвращает проверяемый результат, редакция может продолжить с расшифровкой.
- Для приватного MP4 использовать прямую загрузку в отдельное приватное хранилище. При выборе Vercel Blob выдавать FFmpeg доступ через собственный HTTPS-маршрут с ограниченным по сроку разрешением на один объект. Проверять точный хост, привязку к задаче, время ожидания очереди и повтор чтения. Токен Blob остаётся внутри приложения. [Vercel Private Storage](https://vercel.com/docs/vercel-blob/private-storage)
- В текущем списке фильтров API FFmpeg отсутствуют ebur128 и silencedetect. Для структурированного отчёта требуется ограниченный профиль на существующем сервисе. Его готовность подтверждается ответом API, а не выводом локального скрипта.

## Живая приёмка

1. Gemini, расшифровка. На коротком украинском тексте проверить структурированный ответ, существующие ID реплик, цитату и обоснованный интервал.
2. Gemini, публичный YouTube. На разрешённом коротком ролике проверить, принимает ли его выбранная модель. Записать результат или причину отказа. Проверить переход на импорт расшифровки.
3. Gemini, полный MP4 со звуком. Использовать короткий собственный клип с различимыми репликами в начале, середине и конце. Сверить, что модель распознала фразы и порядок, а интервалы относятся к полному ролику. Проверить повторный аудит новой версии клипа.
4. Для каждого запроса зафиксировать модель, входные и выходные токены, учитываемые токены размышления, длительность и ставку. Стоимость вычислять по фактическому usage. До отправки утвердить бюджет, число запросов и верхние границы входа и выхода. Повтор после неопределённого результата требует сверки. [Тарифы Gemini API](https://ai.google.dev/gemini-api/docs/pricing)
5. Загрузить тестовый MP4 по приватному маршруту. Проверить успешное чтение существующим FFmpeg, отказ анонимному запросу и отказ после истечения срока. Сверить отчёт по звуку с локальным замером и результат вертикального рендера. Проверить повтор задачи с тем же ключом.
6. Зафиксировать целевое окружение, подтверждённые квоты и результаты. Для полного завершения этапа нужны успешные проверки расшифровки, MP4 со звуком и приватной передачи. Экспериментальный режим YouTube может завершиться документированным отказом при рабочем резервном пути.

## История проверок

Локальная часть проверена. Живые запросы Gemini, приватная загрузка на Vercel и действующий FFmpeg в этом проходе не выполнялись. Для прогона нужны отдельный доступ Gemini для проекта, согласованный бюджет и доступ к приватному тестовому окружению FFmpeg.

### Доступы для прогона

В локальном окружении Viral4Creators есть конфигурация Gemini и Blob. Отдельный ключ Gemini не является техническим условием разовой приёмки, если владелец разрешил использовать действующий аккаунт для тестовых материалов нового проекта. Разовый тест использует четыре вызова: расшифровка, публичная ссылка, исходный MP4 и исправленный MP4. План — короткие материалы до 30 секунд, без платных повторов. Квоты и учёт расходов нового продукта до постоянного запуска настраиваются отдельно.

Прямой URL приватного Blob требует учётных данных хранилища, поэтому передавать его исполнителю без посредника нельзя. Проверка транспорта должна использовать ограниченный доступ к одному объекту либо отдельный тестовый адаптер с эквивалентным ограничением. Рабочие данные и секреты Viral4Creators для этого не копируются.

### Первая попытка живой проверки

Запрос расшифровки завершился транспортной ошибкой без ответа. Запросы YouTube и двух MP4 отклонены с HTTP 400. Отдельный запрос метаданных Argon подтвердил API_KEY_INVALID для локального ключа из production-снимка Viral4Creators. Ни один результат модели и ни один отчёт usage не получены. Ключи не записаны в материалы проекта.

### Проба с рабочим доступом Argon

- Метаданные подтвердили `models/gemini-4-argon`. Украинская расшифровка: корректный JSON с ID u2, точной цитатой и началом 2000 мс. Usage: 156 входных и 41 выходной токен. По ставкам $2/$10 за миллион расчёт составляет $0.000722 за этот ответ.
- Публичная YouTube-ссылка и обе ревизии синтетического MP4 со звуком завершились клиентским тайм-аутом через 50 секунд. Результаты и usage не получены, итоговые расходы по этим запросам неизвестны. Автоматических повторов не было. Подтверждён рабочий путь через импорт расшифровки, а видеоаудит остаётся открытым.
- Приёмка приватной передачи и структурированного отчёта на действующем FFmpeg остаётся открытой.

### Структурированный отчёт FFmpeg

Локальная команда `node scripts/audit-media.mjs FILE` возвращает JSON с длительностью, интегральной громкостью, истинным пиком и интервалами тишины. На двухсекундном AAC-клипе с тоном в первой секунде и тишиной во второй получены −22,5 LUFS, пик −17,6 и интервал 1000–2000 мс. Порог −45 дБ и минимум 500 мс относятся к технической пробе. Продуктовые пороги выпуска определяются редакционным стилем. Команда пока запускается локально. Приёмка на действующем сервере требует отдельного профиля аудита и проверенного маршрута приватной передачи.

Перед повтором Gemini проверить расход по предыдущим тайм-аутам в журнале провайдера. Для видео использовать подтверждённый режим с наблюдаемым статусом операции, если он доступен для выбранной модели и аккаунта.

### Приёмка бинарника на действующем VPS

Тестовый синтетический MP4 передан по SSH в stdin штатного контейнера executor. FFmpeg успешно декодировал изображение и звук, измерил −22,4 LUFS, пик −17,6 и тишину примерно 1,08–2,10 с по шкале фрагментированного MP4. Тест не создавал очередь и не изменял контейнеры или конфигурацию. Подтверждена возможность аудита на штатном бинарнике. Приватная выдача через HTTPS и получение отчёта из API очереди остаются отдельными критериями.

Gemini Interactions API предусматривает фоновый запуск с ID операции и последующим чтением статуса. Поддержку фонового видео именно на Argon в этом аккаунте ещё нужно проверить ограниченным запуском. Предыдущие три тайм-аута остаются с неизвестным расходом. [Background execution](https://ai.google.dev/gemini-api/docs/background-execution)

### Фоновый Gemini · обе видеоревизии приняты

Gemini 4 Argon через Interactions API завершил два фоновых анализа синтетических MP4. Исходник: синий фон, речь «red, blue, green». Исправленный файл: тот же фон, речь «red, yellow, green». Модель правильно вернула визуальный признак и изменение в аудио. Оба результата получены опросом ID без повторной отправки. Локальный файл доказательств содержит только ответы и usage, без входных файлов. Фоновый режим сохраняет вход и ответ у провайдера для чтения по ID, поэтому проба выполнена на синтетических данных.

Суммарно 510 входных и 45 выходных токенов, расчётная стоимость $0.00147 по ставкам $2/$10 за миллион. Расход прежних запросов с тайм-аутом в эту сумму не включён и остаётся неизвестен. Режим YouTube остаётся экспериментальным с подтверждённым резервным путём через расшифровку. Открытая проверка этапа: приватный MP4 → штатная очередь FFmpeg → структурированный отчёт через API.

### Профиль аудита для штатной очереди

Подготовлены ограниченные настройки фильтров в исходниках API и executor Viral4Creators. Парсер принимает отчёт только как объявленный артефакт задачи и отклоняет произвольный путь. 130 тестов парсера и ESLint прошли. Цепочка фильтров дополнительно проверена на работающем FFmpeg 5.1.9 на VPS: метаданные показали −22,415 LUFS, линейный пик 0,131 и начало тишины 1,08 с. Манифест для отправки задачи находится в `src/media/ffmpeg-audio-job.mjs`. Работающая версия сервиса ещё использует старые образы. Для полного зачёта нужен совместный выпуск API и executor и успешное получение артефакта через очередь с приватным HTTPS-входом.

### Кандидаты выпуска на VPS

На VPS собраны два образа-кандидата на базе текущих образов, заменён только скомпилированный allowlist: API e951c3ac2216, executor db8bc240e740. Изолированные контейнеры подтвердили наличие фильтров, а парсер образа API принял фактический манифест аудита. Работающие контейнеры остаются 6ecebb6ee029 и 408abb147f9a. Первый способ сборки через Docker BuildKit ошибочно обращался к registry по локальному ID; сборка прошла с локальными тегами.

Vercel Blob поддерживает подписанный GET на один объект. Для финальной пробы нужен синтетический MP4 в приватном хранилище с точным хостом, разрешённым для входов FFmpeg. Проверить 403 без подписи и после истечения срока, затем через очередь скачать audit.txt и сверить метрики. [Подписанные URL Vercel Blob](https://vercel.com/changelog/signed-urls-are-now-available-for-vercel-blob)

### Профиль на действующем VPS

API e951c3ac2216 и executor db8bc240e740 выпущены с резервной копией SQLite и остановкой приёма на пустой очереди. Первая проверка скачивания артефакта вернула 404 и вызвала откат. Та же задача уже имела succeeded и после повторного получения ссылки артефакт скачался. Повторная выкладка проверена на этом же результате без новой задачи. Сервис ready=true, active.

Задача 64730873-911d-47cf-b3f8-df2dabb045c0 прошла через штатную очередь на публичном MP4 MDN. Повтор отправки вернул тот же ID. Через API скачан audit.txt размером 13 212 байт с метаданными LUFS и true peak. Доступные локальные конфигурации Blob не позволили загрузить тестовый объект: одна указывает на отсутствующее хранилище, другая требует OIDC в подходящем окружении. В действующем allowlist FFmpeg есть публичный Blob, но нет хоста приватного хранилища продукта. Проверка приватного HTTPS-входа остаётся последним открытым критерием.

## Итог 12 ноября 2026

**Этап 1 принят как техническая проба.**

Штатная очередь FFmpeg завершила задачу f444a98f-a97a-4803-9029-0b0716b5e002. Синтетический MP4 выдан через временный HTTPS-маршрут с обработчиком и подписью из кода продукта. Действующее разрешение вернуло HTTP 200. Запросы без разрешения и с просроченной подписью вернули HTTP 403. Повтор с тем же ключом вернул тот же ID. Временный маршрут удалён, исходный список разрешённых хостов восстановлен, сервис отвечает ready=true в режиме active.

Из API скачаны отчёт (7015 байт) и вертикальный MP4 (24 310 байт). FFprobe подтвердил 180×320, H.264 и AAC, длительность 3,008 с. Файл полностью декодируется. VPS измерил −22,825 LUFS, линейный пик 0,129 (около −17,8 dBTP) и тишину 1,00–2,00 с. Локальная проверка того же исходника дала −22,8 LUFS, −17,8 dBTP и тот же интервал. Повторный локальный прогон дал 13/13 тестов.

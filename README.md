# Тінь Шарія

Закритий редакційний застосунок. Основний випуск готується для YouTube у 16:9. Вертикальні Shorts і TikTok — похідні версії зі своїм монтажем і допуском.

## Середовища

- Node.js 22, Next.js, PostgreSQL, Drizzle та Clerk. Встановлення залежностей — `npm ci`.
- `.env.example` містить імена змінних. Для локального запуску задайте `APP_STAGE=development`, точний `APP_ORIGIN`, окрему тестову PostgreSQL і ключі тестового Clerk.
- Preview використовує окремі Neon і Clerk та точний URL розгортання Vercel. Production має власну базу й потребує домену, DNS-записів Clerk і live-ключів. Встановіть `APP_ORIGIN` на точний канонічний HTTPS origin. Позначка в PostgreSQL блокує використання бази іншого середовища.
- `DATABASE_URL` використовує пул Neon. Для міграцій задайте `DATABASE_MIGRATION_URL` прямим URL (`DATABASE_URL_UNPOOLED` з інтеграції Neon) в оточенні оператора. Секрет міграцій не потрібен застосунку Vercel.
- Застосовуйте `npm run db:migrate` з кореня проєкту перед розгортанням. GitHub CI перевіряє міграції на ізольованій PostgreSQL. Збірка Vercel міграції не запускає.
- Для браузерного входу встановіть у Clerk маршрути входу `/sign-in` і реєстрації `/sign-up`. Реєстрація облікового запису не відкриває редакцію без запрошення.

## Доступ

Перший адміністратор спочатку створює обліковий запис у Clerk і підтверджує основну адресу. Оператор запускає `npm run access:bootstrap -- <clerk-user-id>` з налаштуваннями потрібного середовища. Команда працює лише для порожньої таблиці учасників.

Адміністратор створює запрошення на підтверджену email-адресу й передає одноразовий код. Учасник вводить його на `/invite` після входу. Код діє 48 годин, повторний випуск скасовує попередній код. Адміністратор змінює ролі або відкликає доступ у редакції. Зміни застосовуються на наступному серверному запиті.

Автор має доступ до API імпорту джерел. Для імпорту також перевіряється точний Origin. Авторизація інших редакційних операцій підключається разом з їхніми маршрутами.

## Перевірки

`npm run lint`, `npm run typecheck`, `npm test`, `npm run build`. Для тесту приватної передачі медіа потрібні `ffmpeg` та `ffprobe`. Тест PostgreSQL запускається в CI з `RUN_POSTGRES_TESTS=1` на свіжій базі з міграціями.

Результати технічної проби Gemini та FFmpeg наведені в [протоколі етапу 1](stage-1-acceptance.md).

## Аналіз джерел

У картці відео автор обирає версію імпортованого розшифрування й запускає Gemini. Знайдені пропозиції залишаються чернетками. Автор може перенести їх у твердження та доповнити доказами. Погодження виконує інший учасник.

Увімкнення потребує окремого ключа Gemini, моделі, ставок у мікродоларах за токен, дати закінчення дії ставок і місячного ліміту в мікродоларах. Після закінчення дії ставок прийом завдань зупиняється до оновлення конфігурації. Для диспетчера встановіть окремий `CRON_SECRET` у кожному середовищі.

Щоб перевірити завислу задачу, перегляньте її спробу, стан фрагмента та резерв. Якщо відповідь на вже відправлений запит втрачена, резерв лишається заблокованим протягом бюджетного місяця. Ручний повтор потребує згоди автора на можливе повторне списання. Експериментальний аналіз YouTube за посиланням очікує окремої прийомки.

## Монтажні версії

Автор завантажує MP4 до 128 МіБ у картці погодженого сценарію. Для кожного середовища потрібні окреме приватне сховище Blob, клієнтський ключ на VPS FFmpeg і точний хост сховища в списку дозволених входів FFmpeg. Дозвіл на завантаження діє 15 хвилин і обмежений одним шляхом. Ліміт середовища — 512 МіБ монтажних матеріалів, строк зберігання — 30 днів.

VPS повністю декодує перші відео- й аудіодоріжки та повертає SHA-256, тривалість, роздільність, LUFS, dBTP та інтервали тиші. Основний формат випуску — 16:9. Звіт технічної перевірки належить конкретному MP4 і версії сценарію.

## Shorts

На сторінці затвердженого сценарію автор може попросити Gemini запропонувати хук, заголовок, опис і фрагменти за транскриптом; перед складанням усе редагується. Пропозиція прив’язана до поточної затвердженої версії, перевіреного MP4 і наявних таймкодів. Платний виклик створюється тільки після натискання кнопки й використовує спільний місячний ліміт Gemini застосунку.

FFmpeg збирає фрагменти в H.264/AAC MP4 1080×1920, 30 fps, 30–60 секунд. Перед видачею сервіс FFmpeg повторно аналізує повний зібраний файл: SHA-256, точні розміри й тривалість, наявність і повноту аудіо, LUFS, dBTP та інтервали тиші. Невідповідний файл не стає готовою чернеткою.

Після технічної перевірки редактор може запустити окремий повний мультимодальний аудит Gemini. У пакет аудиту входять метадані Shorts та вихідний редакційний пакет; звіт має охопити весь таймлайн і підтвердити отримання як відео, так і звуку. Кожне зауваження потребує коментаря редактора; допуск прив’язаний до точного SHA-256 короткого файла. Коротка ревізія не показується як звичайний майстер-монтаж і не допускається до реєстрації основного випуску. Публікації не створюються автоматично.

Готовий MP4 зберігається в приватному Blob і доступний членам редакції через авторизований маршрут. Файли видаляються після 30 днів через плановий диспетчер.

## Випуски каналу Шарія

`/editorial/youtube-channel` показує останні публічні відео каналу Анатолія Шарія (`UCVPYbobPRzz0SjinWekjUBw`): по 20 на сторінку, за замовчуванням новіші зверху. На поточній сторінці можна сортувати за датою, переглядами та вподобаннями. У картці є дата, тривалість, перегляди, вподобання, коментарі, опис і доступні теги/мова/категорія. Статистика, прихована власником відео, позначається як недоступна, а не як нуль.

Дані читаються сервером через YouTube Data API v3; браузер не бачить API key. Для Production потрібен окремий Secret `YOUTUBE_API_KEY` у Vercel-проєкті `tin-shariia`, з увімкненим YouTube Data API v3. Без ключа сторінка повідомить про налаштування, а не покаже вигадані дані. Доступ до сторінки й JSON-маршруту мають лише учасники редакції.

### YouTube uploads (Stage 13)

OAuth and resumable Shorts-upload support is implemented locally but is not enabled in Production until the Google Web OAuth client is configured. Register this exact callback URI with Google:

`https://tin-shariia.viral4creators.app/api/youtube/oauth/callback`

Set these Vercel Production secrets in project `tin-shariia`: `GOOGLE_YOUTUBE_CLIENT_ID`, `GOOGLE_YOUTUBE_CLIENT_SECRET`, and a separately generated 32-byte base64url `YOUTUBE_TOKEN_ENCRYPTION_KEY`. Do not reuse the public Data API key as an encryption key. The app requests only `youtube.upload` and `youtube.readonly`; refresh tokens and resumable session URLs are encrypted at rest. Uploads require a publisher role, an approved exact Shorts media revision, an explicit visibility selection, and a confirmation bound to the file SHA-256. Upload state is reconciled with YouTube before it can be marked complete. Production channel consent and a private test upload remain required before Stage 13 can be accepted.

### Soniox: редакційне розпізнавання

Увімкніть серверні `SONIOX_ENABLED=true` та `SONIOX_API_KEY` після застосування міграції `0012_soniox_requests`. Використовуйте окремий ключ проєкту. Маршрут `POST /api/editorial/soniox?language=uk` доступний адміністраторам, авторам і редакторам з активною сесією редакції та з того самого origin.

Передавайте тіло `audio/wav` (PCM 16-bit, mono, 16 kHz, до 60 секунд) і UUID у заголовку `Idempotency-Key`. WAV можна підготувати командою `ffmpeg -i input.mp4 -t 60 -map 0:a:0 -ac 1 -ar 16000 -c:a pcm_s16le -fflags +bitexact output.wav`. У відповіді `data.text` та `data.tokens` з `startMs` і `endMs`. Для російського оригіналу використовуйте `language=ru`. Повтор із тим самим UUID повертає 409. Квота — 3 спроби на учасника і 10 на проєкт за добу UTC. Аудіо і текст не зберігаються в базі. Видалення файлу й транскрипції запитується у Soniox після завершення або помилки.

Українська озвучка: `POST /api/editorial/soniox/tts` з JSON `{"text":"…"}` до 650 символів і UUID у `Idempotency-Key`. Результат — MP3 голосом Maya. Квота спільна з розпізнаванням. Gemini пропонує `narrationUk` у плані YouTube Shorts, текст можна відредагувати перед озвучкою.
